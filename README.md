# המאגר האולטימטיבי

מבחני תרגול וסיכומים, רפואת חירום מחזור 29.

## מה יש כאן

| נתיב | תפקיד |
|---|---|
| `data/catalog.json` | **מקור האמת היחיד של הקטלוג.** כל שינוי בתוכן האתר מתחיל כאן |
| `index.html` | הקטלוג הראשי. רשימת המבחנים בתוכו נוצרת אוטומטית מ-`data/catalog.json` |
| `exams/*.html` | המבחנים והסיכומים, אחרי התאמת עיצוב |
| `source/exams/*.html` | הקבצים המקוריים של אביב (לא נוגעים בהם ידנית) |
| `source/overrides/*.css` | תיקוני עיצוב נקודתיים לעמוד מסוים |
| `lib/transform.js` | ההתאמה האוטומטית: פונטים, צבעים שטוחים, רדיוסים, בלי אימוג׳י, סרגל חזרה למאגר |
| `theme/exam.css` | שכבת העיצוב המשותפת לכל המבחנים |
| `admin.html` + `api/*` | ניהול: העלאת מבחנים חדשים בזמן שהאתר באוויר |
| `scripts/sync-catalog.js` | מזריק את הקטלוג ל-`index.html` ובודק שהוא תקין |

## הכלל החשוב: מקור אמת אחד

הקטלוג נמצא **רק** ב-`data/catalog.json`. אחרי כל עריכה שלו:

```
npm run sync
```

הסקריפט בודק שאין מזהים כפולים, שכל השדות קיימים, שכל מבחן שמסומן כזמין באמת מצביע על קובץ קיים — ורק אז מזריק את הקטלוג ל-`index.html`. אם משהו לא תקין הוא נעצר ומסביר מה.

**לעולם לא עורכים את שורת `BUILTIN` שבתוך `index.html` ידנית.** היא נדרסת בכל סנכרון.

## מבנה פריט בקטלוג

```json
{
  "id": "b15",
  "year": "year1",
  "sem": 2,
  "subject": "נפרולוגיה",
  "name": "נפרולוגיה - מבחן תרגול",
  "type": "מבחן",
  "status": "ready",
  "url": "exams/16.html",
  "builtin": true
}
```

| שדה | ערכים |
|---|---|
| `id` | מזהה ייחודי. לא משנים אותו אחרי שהוא באוויר |
| `year` | `year1` / `year2` / `year3` |
| `sem` | `1` או `2` |
| `subject` | שם הקורס. **חייב להיות זהה בדיוק** בין פריטים של אותו קורס, אחרת הם יתפצלו לשתי קבוצות |
| `name` | מה שכתוב על הכפתור |
| `type` | `מבחן` או `סיכום` |
| `status` | `ready` (זמין) / `pending` (בבדיקה) / `empty` (בקרוב, בלי קובץ) |
| `url` | נתיב לקובץ. חובה לכל פריט שאינו `empty` |
| `builtin` | `true` למבחן שנמצא בקוד, `false` למבחן שהועלה דרך הניהול |

הסדר שבו הפריטים מופיעים בקובץ הוא הסדר שבו הם מופיעים באתר. הקטלוג הנוכחי מסודר לפי סדר הקורסים בתואר.

## איך מוסיפים מבחן

שתי דרכים, ושתיהן מסתדרות זו עם זו:

**דרך הניהול (כשהאתר באוויר):** נכנסים ל-`/admin.html`, ממלאים את הטופס. חשוב לבחור את שם הקורס מתוך ההשלמה האוטומטית, כדי שהמבחן ייכנס לקבוצה הנכונה. ברגע שקורס מקבל מבחן אמיתי, שורת ה"בקרוב" שלו נעלמת מעצמה.

**דרך הקוד:** מוסיפים את הקובץ ל-`source/exams/`, מריצים `npm run build:exams`, מעדכנים את הפריט ב-`data/catalog.json` מ-`empty` ל-`ready` עם ה-`url`, ומריצים `npm run sync`.

## פריסה ל-Vercel

1. להעלות את התיקייה ל-GitHub (או `vercel deploy` מהתיקייה).
2. ב-Vercel: **Storage → Create → Blob**, ולחבר לפרויקט. זה מוסיף אוטומטית את `BLOB_READ_WRITE_TOKEN`.
3. **Settings → Environment Variables**: להוסיף `ADMIN_PASSWORD` עם סיסמה משלכם.
4. Redeploy.

> **אבטחה:** חובה להגדיר `ADMIN_PASSWORD`. בלי זה נשארת סיסמת ברירת המחדל שבקוד, וכל מי שרואה את הריפוזיטורי יכול להיכנס לניהול. אל תכתבו את הסיסמה האמיתית בקובץ הזה או בשום קובץ אחר בפרויקט.

בלי Blob האתר עובד רגיל, רק ההעלאה מהניהול לא פעילה.

## ניהול

`/admin.html` → סיסמה → טופס העלאה. הקובץ עובר את אותה התאמת עיצוב כמו שאר המבחנים (אפשר לבטל בצ׳קבוקס), נשמר ב-Blob, ומופיע בקטלוג מיד. אפשר גם למחוק העלאות ולהסתיר פריטים מובנים.

**מסך הניהול דורש שרת.** פתיחה של `admin.html` בלחיצה כפולה מהמחשב לא תעבוד, והדף יגיד את זה. צריך או את האתר ב-Vercel, או שרת מקומי.

## להריץ מקומית

```
npm install
npm run dev
```

ואז http://localhost:3000. העלאות מקומיות נשמרות בתיקייה `.data/` (לא עולה ל-git).

את הקטלוג והמבחנים אפשר לראות גם בפתיחה ישירה של `index.html` בדפדפן, בלי שרת — רק הניהול לא יעבוד ככה.

## לבנות מחדש את המבחנים

אחרי שינוי ב-`theme/exam.css` או ב-`lib/transform.js`:

```
npm run build:exams
```
